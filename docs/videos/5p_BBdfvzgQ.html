Making $$$ with Loop Engineering

Channel: Greg Isenberg · Published: 2026-07-20 · Length: 40 min · Watch on YouTube

TL;DR

"Loop engineering" gets applied beyond coding to whole business functions: SEO, Facebook ads, and product development, each run as a continuous build-verify-learn cycle with an objective metric as the stop condition. Greg Isenberg and guest Ellie walk through a working SEO loop against Google Search Console, live numbers included, plus lighter sketches of an ads loop and a product-feedback loop.

Walkthrough

The concept borrows directly from the lean-startup build-measure-learn cycle and from Toyota-style lean manufacturing: constant iteration against a real, measurable outcome rather than a single shipped attempt. Applied to an AI agent, the same shape becomes build, verify, and learn, with a hard stop condition so the loop doesn't run forever without a reason. In an engineering context that stop condition might be Claude Code's /goal running until a signup flow actually works in the browser, or an eval score for a feature (their example is an email-categorization AI) climbing past a 90% accuracy threshold before the loop is allowed to stop adjusting the prompt or model choice. In a business context, the same structure works as long as there's some objective metric feeding back into the system, which is really the whole trick: find the metric first, then let the loop run against it.

The SEO loop is the one they build out in real detail. The objective metric is simply Google ranking position for a target term. The setup starts with connecting an agent to real data: Google Search Console (which shows current rankings and the pages currently ranking above yours for terms you want) and DataForSEO as a competitive-research API. From there, the loop mirrors what an SEO agency actually does: audit the site for quick technical wins (meta tags, JSON-LD, sitemaps), then experiment with specific underperforming terms, make changes, and check back a month later to see whether rankings moved up or down, keeping a markdown log of what was tried so the agent doesn't repeat failed experiments. He shows this running live against draftfantasy.com, a small side project, where a term ranked fourth is being pushed toward the top three; on his AI product Inbox Zero, the same loop is already producing "numbers going in the right direction" a few months in. Cost is the other half of the pitch: each run is roughly monthly, not continuous, so a full SEO loop costs an estimated few dollars a month in tokens, trivial next to what an SEO agency or freelancer would charge, and effectively already covered if you're on a higher-tier Claude or Codex plan.

The Facebook ads loop follows the same shape with a different metric: run multiple ad variants, let the agent read performance data, and double down on winners while cutting losers, the same volume game a human media buyer already plays but at a pace and breadth an agent can sustain more easily. They're candid that AI-generated ad creative isn't yet as strong as top human work, so the more realistic version blends a human-shot base (a person talking into a phone for 30 seconds) with AI doing the editing and iteration around it, rather than a fully AI-generated ad. The most ambitious loop discussed is a product-feedback loop: an agent reading customer feedback, analytics (PostHog), and error logs (Sentry) to prioritize pain points, prototype fixes, and ship them, judged against whatever core metric matters most, whether that's retention, DAU/MAU, or virality. They flag this as the "holy grail" version and, honestly, riskier to run unsupervised on a real business today, more a preview of where things are heading than something to hand over fully right now.

Standout moments

The most useful practical detail is the cost framing: "I wouldn't be shocked if this cost you less than $5 in tokens to run one time" for a monthly SEO check, versus thousands for an agency retainer, which reframes the whole idea from a coding curiosity into a genuinely cheap business habit. And the closing advice on scope is worth remembering before starting one of these: don't set a loop's target as something vague and huge like "100,000 followers" — find the smallest verifiable outcome (more likes on individual posts, not follower count) and loop against that instead.

Why this matters for my work

The SEO loop recipe transfers directly to join.com's marketing repo: Search Console plus an SEO-competitor API is exactly the kind of agent-over-a-warehouse pattern worth prototyping for organic/content work, and the monthly-cadence, cheap-token framing removes the usual "won't this get expensive" objection before it's raised. It's also good amir-azimi course material as a concrete, non-coding-specific illustration of what "agent loop" actually means for a marketing or ops audience, since most loop-engineering content stays purely in the coding domain.

The underlying discipline, pick the metric first and only then build the loop against it, is also a useful gut-check for bi-data work generally: it's the same instinct behind a good tracking plan or a well-scoped eval harness, just applied to a marketing function instead of a model. Given the digest's own publish loop already runs on roughly this shape (score against a rubric, publish what passes, log what didn't), it's a small but real validation that the pattern generalizes past coding into ordinary recurring business work, which is exactly the pitch worth making to non-technical teams who assume "agent loop" only means software.
