How I Make Opus Think Like Fable (5 easy steps)

Channel: Nate Herk | AI Automation · Published: 2026-06-30 · Length: 10 min · Watch on YouTube

After spending a few thousand dollars in Fable usage credits testing what it's actually good for, the central claim here is that the model isn't the moat — the process is. The illustration: give a total beginner Fable 5 and an expert like Andrej Karpathy the much weaker Sonnet 3.7, and the expert still builds something better, because how you instruct a model and the loops you build around it matter more than raw model intelligence. A more controlled version of the same test: running identical dynamic workflows with Fable orchestrating Fable sub-agents versus Fable orchestrating Opus or Sonnet sub-agents produced roughly equivalent results at a fraction of the cost — the direct evidence that you can't keep a model's raw intelligence, but you can keep its process.

The practical response is to treat Fable less like a workhorse and more like a teacher — extract how it approaches a problem and transplant that discipline onto cheaper models, rather than defaulting to Fable for everything. After reading through Fable's leaked system prompt with Fable itself and picking out the operating principles worth keeping (verify rather than assume something is current just because it's in memory, confirm a file actually exists rather than assuming it because a prompt implies it, address an ambiguous query directly before asking a single clarifying question, calibrate research depth to the task — one source for a simple fact, five to ten for deeper comparative research), those principles get compiled into an installable skill file the creator calls "Fable mode."

Fable mode is structured around five gates: scoping (before any work begins), evidence (gathering before reasoning), adversarial reasoning (actively arguing against your own plan to find what could go wrong, which the video argues is specifically where Fable is unusually strong — planning that includes genuine devil's-advocate scrutiny rather than just a step list), verification (before declaring anything done), and calibration. Applying this skill file to Opus 4.8 is described as making the model "feel elevated" — closing much of the practical gap with Fable at a fraction of the cost, and portable to any model, including GPT or open-source models, since the skill only encodes a working discipline, not anything Fable-specific.

The reasoning behind why this works ties back to dynamic workflows specifically: if Fable plans a workflow, stress-tests every likely failure mode as part of that plan, and then hands execution to cheaper Sonnet workers who report back for Fable to review and iterate on, the quality holds up close to a full Fable-to-Fable run — because the expensive reasoning happened once, up front, in the plan, not repeatedly across every execution step.

The second half introduces a concrete model-routing table: list every model available in your toolkit alongside a cost score (higher meaning cheaper) and separate ratings for intelligence (how well it reasons, reviews code, catches issues) and taste (creativity, UI/UX judgment, out-of-the-box thinking). This table becomes the basis for assembling dynamic agent teams deliberately rather than defaulting every sub-agent to the same model — a demonstrated test compared an Opus orchestrator delegating to a mix of Sonnet and Opus workers against the same orchestrator delegating entirely to Haiku "scouts": the Haiku-only version came out roughly three times cheaper with an equivalent result, mirroring the same finding from the Fable-vs-cheaper-worker comparison.

The closing point is framed around the fact that Fable access itself isn't guaranteed to be permanent (subscriptions can change, models can be pulled), which the creator uses to argue for investing in owned processes and methodology rather than any single vendor's model — the actual asset is the skill file and the routing logic, both of which are portable regardless of which model happens to be available next month.

The Fable-mode skill file and the cost/intelligence/taste routing table are both directly reusable prompting techniques — the routing table in particular is a concrete, teachable framework for anyone building multi-agent workflows in the vault or for client work, independent of which specific frontier model is current at the time.
