14 GENIUS Ways to Give Claude Code SUPERPOWERS

Channel: Simon Scrapes · Published: 2026-06-12 · Length: 29 min · Watch on YouTube

A year ago, the top tip for Claude Code was to plan everything before letting it build. Now it's to flip on auto mode and stop approving every permission. This video packs fourteen of the highest-leverage setup decisions, gathered from watching thousands of users in a paid community, into one video, arguing that the gap between people treating Claude Code as a slightly better chatbot and people running their business through it is a handful of setup choices, not prompting skill.

The newest and biggest feature is ultra code, which comes from dynamic workflows. Out of the box, Claude plans and executes in a single context window, which degrades on long jobs in three specific ways: it declares itself finished before it actually is, it's overconfident when judging its own work, and it slowly loses the original objective as context grows and gets compacted. Ultra code fixes this by letting Claude write its own workflow for a specific task, spinning up a team of sub-agents, each with a clean context and one job, coordinated together. Anthropic documents six patterns it composes from: classify-and-act (routing tasks by type, like sorting support tickets), fan-out-and-synthesize (splitting work across parallel researchers and merging results, the standard shape for deep research), adversarial verification (a second agent tries to break the first agent's claims), generate-and-filter (produce many options, then deduplicate down to the strongest, good for brainstorming), tournament (agents compete for a winner), and loop-until-done. A live demo runs a deep-research task on Claude Code's own latest features: it fans out five scouts across sources, deep-reads the strongest eight, adversarially verifies twelve key claims, and synthesizes a report, using 670,000 tokens and 26 agents over 13 minutes, an explicit reminder this is not for small jobs.

Auto mode remains the top recommendation for saving time: a background classifier lets safe actions through automatically and only interrupts for genuinely risky ones, letting you physically walk away from the desk. Paired with it are two commands for autonomous long-running work: loop, which repeats a prompt on an interval (capped at three days), and goal, which defines a condition Claude must satisfy before it's allowed to stop, checked after every turn. Chained together, a task like "clear my inbox daily" becomes self-verifying and self-scheduling; a live Gmail-triage demo completes in one turn once authorized.

On skills, the video argues most people build them badly: without clean triggering descriptions and progressive disclosure (detail loading only when needed), Claude activates them inconsistently and burns tokens. Done well, a skill is a concise, reusable instruction guide, ideally reusable across systems rather than hyper-specific, so a copywriting skill should work for any writing task, not just one ad format. The deeper unlock is skill systems: several skills chained so the output of one feeds the next, turning individual building blocks into an end-to-end pipeline. The video's own social-content system is eighteen chained skills covering brand voice, visual identity, scraping, and image generation sub-agents, and the value is explicitly said to live in the chain, not the individual parts.

On tool connections, MCP keeps a tool's full definition loaded for the entire session, which is worth it for rich, daily, multi-tool interactions (a live CRM, for example) but wasteful for a single occasional action, where a CLI call that runs once and forgets the infrastructure is cheaper. On memory, the video repeats its now-familiar three-job framework (storage, injection, recall), noting Anthropic is "quite behind" here relative to open-source frameworks like mem-search, Hermes, and open-claw, and that a custom-built system pulling the best of each, plus access control for team use, is what they've settled on. The video closes on two habits: the "slot machine" principle (when Claude goes wrong, don't correct it further; use the rewind feature to return to a clean checkpoint and try again with better context, since correcting in place just compounds broken context) and the sub-agent-versus-skill distinction: a skill is what Claude knows how to do, a sub-agent is who does the work in isolation, useful when you need different tools, permissions, a different model, or to run several jobs in parallel without polluting the main conversation.

Standout moments

The reframe that "a skill is basically a sub-agent without a role" because a role is just context applied to a task is a genuinely clarifying way to resolve what's normally a confusing distinction. The live ultra-code demo's raw numbers, 670,000 tokens and 26 agents for one deep-research pass, are a useful gut-check on when this pattern is actually worth reaching for versus overkill.

Why this matters for my work

The six named dynamic-workflow patterns give a concrete vocabulary for designing multi-agent BI and content pipelines rather than reinventing ad hoc structures each time, and the skill-system chaining example is a direct template for content and reporting pipelines in both the BI and marketing repos. So I could pick one recurring BI deliverable and rebuild it as a chained skill system rather than a single monolithic prompt, then measure whether output consistency improves.
